## Architecture

**Stack:** Next.js 14 App Router · TypeScript · Tailwind CSS · Supabase (Postgres + Auth) · OpenAI `gpt-4o-mini`

### Data flow for adding a word

`AddWordForm` (client) → `POST /api/words` → inserts into `words` table → calls `generateExercises()` (OpenAI, non-fatal if it fails) → inserts into `exercises` table → inserts into `word_progress` with `next_review = now()`.

Exercises are generated **once** at word creation and cached in the DB. Never regenerate on read.

### Supabase client pattern

Two separate clients exist and must be used in the right context:

- `lib/supabase/client.ts` — `createBrowserClient`, for `'use client'` components
- `lib/supabase/server.ts` — `createServerClient` with cookie forwarding, for Server Components and Route Handlers

The server client must be instantiated **inside** each Server Component or Route Handler (not at module scope) because it calls `cookies()` from `next/headers`.

### Auth

Auth is handled in `middleware.ts` via `@supabase/ssr`. It refreshes the session on every request and redirects:
- Unauthenticated users hitting `/dashboard`, `/add`, `/practice` → `/login`
- Authenticated users hitting `/login` → `/dashboard`

All API routes re-verify auth with `supabase.auth.getUser()` server-side — never trust client-sent user IDs.

### Spaced repetition logic

Lives in `app/api/practice/[wordId]/route.ts`:
- Correct → `interval = Math.min(interval * 2, 365)`, `next_review = now + interval days`
- Incorrect → `interval = 1`, `next_review = tomorrow`

Words are due for practice when `word_progress.next_review <= now()`. Words with no `word_progress` record are also included (treated as immediately due).

### Database security model

All four tables (`words`, `exercises`, `reviews`, `word_progress`) have RLS enabled. Key constraint: `exercises` and `reviews` insert policies enforce that the referenced `word_id` belongs to the authenticated user — this is checked at both the application layer (Route Handlers) and the database layer (RLS). Any new write routes that reference a `word_id` must verify ownership explicitly.

### UI conventions

- shadcn-style components live in `components/ui/` — hand-written, not generated by the shadcn CLI
- CSS variables for the color system are defined in `app/globals.css`; primary accent is violet (`hsl(263 70% 50%)`)
- `cn()` from `lib/utils.ts` is the standard utility for merging Tailwind classes
- All shared types are in `lib/types.ts`
- Layout (sidebar) is defined per route group: `app/dashboard/layout.tsx`, `app/add/layout.tsx`, `app/practice/layout.tsx` — all three are identical and render `<Sidebar />`
